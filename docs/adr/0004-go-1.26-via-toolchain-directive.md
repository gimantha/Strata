# ADR 0004: Target Go 1.26 through a toolchain directive

Status: accepted
Date: 2026-08-22

## Context

The contract specifies Go 1.26 or a newer compatible 1.x. Development and CI machines
frequently carry an older Go in `PATH` - the machine this was built on had 1.24.7 - and
pinning the language version in `go.mod` without a plan for that would break builds for
anyone not already upgraded.

## Decision

`go.mod` declares `go 1.26` and `toolchain go1.26.0`. With the default `GOTOOLCHAIN=auto`,
any Go 1.21 or newer fetches and uses the correct toolchain automatically. CI resolves the
version from `go.mod` rather than pinning it separately, so the two cannot drift.

## Alternatives

- **Declare `go 1.24` to match the installed toolchain.** Rejected. It silently targets an
  older language version than the contract requires, and the divergence would be
  discovered much later.
- **Require developers to install Go 1.26 manually.** Rejected. The toolchain directive
  already solves this, and a manual step is a step that gets skipped.
- **Vendor a toolchain.** Rejected as unnecessary weight.

## Trade-offs

The first build in a fresh environment downloads a toolchain, which needs network access
and a little time. Environments that pin `GOTOOLCHAIN=local` will fail with a clear
version error, which is the correct outcome.

## Migration impact

Raising the minimum Go version means editing both directives together. Nothing else in the
repository depends on the version.
